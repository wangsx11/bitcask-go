# M1 API、错误与生命周期实现记录

## 完成范围

M1 已完成配置隔离、错误传播和数据库生命周期收紧：

- `DefaultOptions()` 每次返回独立配置，`Open` 再做值复制；调用者后续修改配置不会影响已打开的 DB。
- `Indexer` 的 `Put`、`Get`、`Delete`、`Size`、`Iterator` 全部返回 error；B+Tree 打开、事务和 CRUD 失败不再 panic。
- 未知索引与 IO 类型返回显式错误；MMap 的 `Write` 和 `Sync` 返回只读错误。
- 新增稳定的 `ErrClosed`、`ErrCorrupted`、`ErrUnsupported` 和 `ErrInvalidOptions`，可通过 `errors.Is` 判断。
- `Open` 失败会关闭索引和已打开数据文件并释放目录锁，且失败清理不会额外写入 `seq-no`。
- `Close` 幂等，先阻止新操作并等待 Merge，再依次 sync、保存序列号、关闭索引和数据文件、释放目录锁。
- hint、merge-finished 和 seq-no 辅助文件均显式关闭；关闭错误与原始错误合并返回。
- `Stat` 返回 `(*Stat, error)`，目录统计失败不再 panic。

## API 调整

M1 按路线图允许破坏性 API 调整。主要迁移如下：

```go
opts := bitcask.DefaultOptions()
db, err := bitcask.Open(&opts)

batch, err := db.NewWriteBatch(bitcask.DefaultWriteBatchOptions)
iterator, err := db.NewIterator(bitcask.DefaultIteratorOptions)
keys, err := db.ListKeys()
stat, err := db.Stat()
err = iterator.Close()
```

旧拼写 `fio.StanderFIO`、`data.ErrinvalidCRC` 和 `ErrMergIsProcess` 保留为兼容别名；新代码分别使用 `fio.StandardFIO`、`data.ErrInvalidCRC` 和 `ErrMergeIsProcessing`。

## 参数契约

- `DirPath` 不能为空；已存在路径必须是目录，目录创建和权限错误原样返回。
- `DataFileSize` 必须大于 0。
- `IndexerType` 只能是 BTree、ART 或 BPlusTree。
- `DataFileMergeRatio` 必须是 `[0, 1]` 内的有限数值，NaN 非法。
- `BytesPerSync` 是无符号阈值；0 表示禁用按累计字节 sync，其余无符号值均有效。
- `WriteBatchOptions.MaxBatchNum` 必须大于 0，提交记录数仍不得超过该上限。

## 失败路径覆盖

新增或扩展的测试覆盖：

- 默认配置与调用者配置的隔离。
- Merge 使用配置副本，不改写主 DB 或调用者配置。
- nil、空目录、文件路径、非法文件大小、非法索引和非法 merge 比例。
- 损坏数据导致 Open 失败后，数据文件和目录锁可以立即重新打开。
- B+Tree 索引打开失败后释放目录锁。
- B+Tree 在空目录首次打开和关闭后重开时均可创建 WriteBatch。
- 无权限目录打开失败。
- Close 重复调用以及关闭后 Put/Get/Delete/Sync/Stat/ListKeys/Fold/Backup/Merge/Batch/Iterator。
- B+Tree 关闭后的 Put/Get/Delete/Size/Iterator 返回 error。
- MMap 只读行为与未知 IO/索引类型。
- Stat 的目录统计错误返回。
- 内存索引关闭时不再生成无用的 seq-no 文件。
